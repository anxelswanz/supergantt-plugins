> 状态：P0–P1 已实现（`plugins/spare-parts`），P2 盘点已实现，P3 发货单识别部分实现，P4 飞书未开始  
> 归属：`supergantt-plugins` → `plugins/spare-parts`  
> 变更：本版按 2026-11-04 的决定改写 —— 按项目隔离、记录更改人、手动同步、不允许负库存、整数、无借用、无多位置、发货单按数量入库、AI 直接写入不确认

## 0. v1 → v2 改了什么

| 项 | v1（初稿） | v2（本版） |
|---|---|---|
| 归属 | 全机一份台账 | **按项目一份**（`inventory-<项目 id>.json`），没有打开项目就不能用 |
| 操作人 | 未定义 | 每条日志 / 条目记 `by`（当前登录账号），条目记 `createdBy` |
| 负库存 | 可配置 | **不允许**，使用数 > 库存直接拒绝 |
| 数量 | 允许小数（未定） | **全部整数** |
| 借用 / 多位置 | 列为「不做」 | 维持不做，且不预留字段 |
| 盘点期间有变动 | 待定 | **库存直接改成实盘数**；`before` 取提交那一刻的系统数 |
| 识别入口 | 草稿 → 用户确认 | **AI 直接写入**，不做确认；错误在台账里改，或整批撤销 |
| 识别对象 | 零件照片为主 | **发货单 / 装箱单为主**，按单据数量**入库**（不是每条 1 件） |
| 识别产出 | 草稿 JSON 交给插件 | AI 只加**自定义列**，核心列固定；Agent 可直接调 CLI 写库 |
| 飞书 | 定时自动同步 | **只有手动「同步」**；只推不拉；备件表两边都有的行更新本地最新库存 |
| 序号 | 未定义 | 每项目一条单调递增的 `seq`，从 1 开始，不复用 |

## 1. 目标与边界

### 1.1 一句话

在 SuperGantt 的某个项目里管一份**备件库存**：录入（手动 / 发货单）、搜关键字、按字段筛选、按「使用」扣库存、按「盘点」校准库存，每一次变动都留一条可追溯的日志，并能把备件表和日志表**手动**推到飞书多维表格。

### 1.2 做

| 能力 | 阶段 |
|---|---|
| 按项目建台账；新增 / 编辑 / 归档条目；搜索 + 分类 / 单位 / 状态 / 使用时间筛选 | P0 ✅ |
| 使用：扣库存，必须指定设备（Entity），可指定领用人，写日志 | P1 ✅ |
| 入库 / 调整 / 整批撤销导入 | P1 ✅ |
| 盘点：实盘数为准，盘盈盘亏一次性纠正，生成盘点批次凭证 | P2 ✅ |
| 库存变更日志：按备件 / 设备 / 类型 / 日期筛选，导出 Markdown | P1 ✅ |
| 发货单识别：应用内粘贴文本 → AI 结构化 → 预览 → 写入 | P3 部分 ✅（图片、Agent 直调 CLI 在 P3 剩余部分） |
| Skill：Claude Code 直接建表（走 `gantt spare` 子命令） | P3 |
| 飞书：建「备件表 + 库存变更日志表」，日志表的备件字段是关联记录；或关联已有表；手动同步 | P4 |

### 1.3 不做

- **不做借用 / 归还状态**：入库即归还，日志足够还原。
- **不做多位置**：一个条目只有一个字符串位置，不做分仓、不做按位置拆行。
- **不做负库存**、不做小数数量、不做多设备一次使用。
- **不做采购流程、替代件、BOM**。
- **不做飞书反向同步**：飞书那边只读（可以筛、可以做视图），改了不回来。
- **不把库存写进 `gantt.db`**：插件数据独立，项目导出、云备份都不带备件（见 §12.1）。

## 2. 数据模型

存储：插件目录 → `data/accounts/<账号 uuid>/inventory-<项目 id>.json`，经宿主 `api.storage` 原子写。

```jsonc
{
  "version": 1,
  "rev": 17,
  "meta": {
    "createdAt": "…", "updatedAt": "…",
    "checks": [ /* 盘点批次，见 2.4 */ ]
  },
  "parts":     [ /* Part 2.1 */ ],
  "logs":      [ /* Log 2.2 */ ],
  "entities":  [ /* Entity 2.3 */ ],
  "imports":   [ /* Import 2.5 */ ]
}
```

id 一律 `crypto.randomUUID()` 派生（`p_…` / `l_…` / `e_…` / `c_…` / `imp_…`），不跨设备流转也不怕撞。

### 2.1 Part（备件）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定身份 |
| `seq` | int | **项目内序号**，从 1 开始，永不回收 |
| `name` | string | 必填 |
| `sku` | string | 物料号 / 型号；**飞书匹配键**；非归档条目内不允许重复（不分大小写） |
| `spec` | string | 规格 |
| `category` | string | 自由文本 + 已有值下拉 |
| `location` | string | 存放位置（单值） |
| `unit` | string | 默认 `个` |
| `qty` | int | 当前系统库存，≥ 0 |
| `minQty` | int \| null | ≤ 它标「库存不足」 |
| `note` | string | |
| `fields` | `{key,label,value}[]` | **自定义列**：发货单上多出来的列（单价、批次、供应商料号…） |
| `archived` | bool | 归档而不是删除（日志还要引用） |
| `createdAt` / `createdBy` / `updatedAt` / `updatedBy` | | 「谁改的」 |

**核心列固定**：`seq / name / sku / spec / category / unit / qty / note` 是搜索、使用、盘点、飞书都依赖的列，AI 不能改。发货单多出来的列只能进 `fields`，可以改名、可以删。

### 2.2 Log（库存变更日志）

| 字段 | 说明 |
|---|---|
| `id` | |
| `partId` / `seq` | 指向条目；`seq` 冗余一份，条目没了也读得懂 |
| `type` | `create` / `import` / `use` / `receive` / `check` / `adjust` |
| `qty` | 有符号增量 |
| `before` / `after` | 库存快照，不用反推 |
| `entityId` / `entityName` | 用在哪台设备（使用必填） |
| `personId` / `by` | 领用人 / 操作人（账号名） |
| `note` / `at` | |
| `importId` / `raw` / `confidence` | 来自 AI 导入时带上；`raw` 是单据上的原文行 |
| `checkId` | 盘点批次 |
| `revertedBy` | 被哪条反向调整冲掉 |

### 2.3 Entity（设备）

`{ id, name, kind, note, archived, createdAt }`。使用弹窗里可搜索、可当场新建；同名（不分大小写）不重复建。

### 2.4 盘点批次

```jsonc
{ "id": "c_…", "at": "…", "by": "张三", "note": "",
  "scope": { "kind": "all" },
  "lines": [{ "partId": "…", "seq": 3, "name": "…", "systemQty": 5, "countedQty": 4, "delta": -1, "logId": "l_…" }],
  "summary": { "gain": 1, "loss": 2, "gainQty": 3, "lossQty": 2 } }
```

不可修改，只追加。点日志里的盘点记录可以追溯整批。

### 2.5 Import（导入批次）

`{ id, at, by, source, count, revertedAt? }`。`source` 是单号或来源说明（发货单上没有单号时由用户 / AI 填）。

## 3. 界面

工具条新增一档 **备件**（`spare-parts.view`）。没有打开项目时整视图显示「备件跟着项目走 —— 先打开一个项目」。

```
备件  产线改造   [清单 12] [日志]                    ＋新增  盘点  从发货单导入
[⌕ 名称/SKU/规格/分类/备注] [状态▾] [使用时间▾] [分类▾] [单位▾] [含已归档]
12 条 · 3 条库存不足 · 最近一次盘点 2026-10-30
序号 名称        SKU       规格    分类  库存  最近使用       操作
1    伺服电机    SM-400W   400W    电机  4个   10-30（2）     使用 入库 编辑 …
```

- **搜索**：名称 / SKU / 规格 / 分类 / 备注，大小写无关，边打边筛。
- **筛选**：状态（不足 / 没库存 / 正常）、使用时间（从未 / 30 天 / 7 天）、分类、单位、含已归档。不同字段之间「且」。
- **排序**：库存不足置顶，其余按序号。
- **行操作**：使用（主）、入库、编辑、`…`（单条变更记录）。

### 3.1 使用

```
使用 · 伺服电机（当前 4 个）
数量      [1]
用在哪    [Robot1 ▾]   （选不到就在下面输入新名字，会当场建）
领用人    [张三 ▾]（项目负责人）
备注      [ ]
              使用后剩余 3        [取消] [确认使用]
```

- 数量正整数，> 库存直接拒绝（提示当前只有几个）。
- 设备必填；新建设备和扣库存在**同一次写入**里，要么都成，要么都不成。
- 领用人可选，取 `api.data.people`（当前项目的负责人名单）。

### 3.2 盘点

```
盘点                            已填 12/30 · 盘盈 1 · 盘亏 2
序号 名称      系统   实盘   盈亏
1    伺服电机   4     [3]    -1
…
盘点说明 [ ]                                    [取消] [确认盘点]
```

- 只填实盘数；空缺 = 没盘，不动。
- 确认后库存**直接变成实盘数**（盘盈盘亏一次纠正）。
- 写一条 `check` 日志（`before` 为提交那一刻的系统数），并入盘点批次。

### 3.3 日志

按备件 / 设备 / 类型 / 日期筛选；列：类型、备件、设备、数量、库存变化、领用人 / 操作人、时间。可导出 Markdown（走宿主 `export.document`，可存 .md 或 Word）。

## 4. 库存规则

所有会动库存的动作都在 `main.js` 上半部分的领域层，视图只收集输入：

| 动作 | 库存 | 日志 | 拒绝条件 |
|---|---|---|---|
| 新建 | `0 → 初始库存` | `create`（初始为 0 时不写） | 名称空、初始为负、SKU 重复 |
| 导入 | `+ 单据数量` | `import` | 同上 |
| 使用 | `q − n` | `use` | n ≤ 0、n > q、没选设备、条目已归档 |
| 入库 | `q + n` | `receive` | n ≤ 0 |
| 调整 | `q ± n` | `adjust` | delta 为 0、不写原因、扣成负 |
| 盘点 | `q → 实盘` | `check`（差异为 0 不写） | 一条都没填、实盘为负或非整数 |
| 撤销导入 | 反向 | `adjust` | 这批没有未撤销的日志 |

**不变量**（写回前校验，违反就拒绝写入并报错）：

1. `log.after = log.before + log.qty`
2. `part.qty` = 该条目最后一条日志的 `after`
3. 库存 ≥ 0

## 5. 发货单识别

### 5.1 应用内（已实现）

「从发货单导入」→ 粘贴单据文本 → 宿主 `api.ai.ask(prompt, { schema })`（零工具，只读提示词、只吐 JSON）→ 预览表（可勾选、可改名、可改数量）→ 写入。

输出契约：

```jsonc
{ "source": "单号或来源",
  "items": [{ "name", "sku", "spec", "category", "unit", "qty", "fields": [{ "label", "value" }], "confidence" }] }
```

规则：同一货号多行合并、数量相加；单上的单价 / 金额 / 批次进 `fields`；不编造 SKU。

### 5.2 Agent / CLI（P3）

Agent 不只是「生成草稿」，而是**直接建表**。走已带的 Skill `gantt-spare-parts`，底层是 CLI 的 `gantt spare` 子命令：

```bash
gantt spare project --json                       # 拿到当前 / 指定的项目 id 和台账路径
gantt spare import <draft.json> --project <id> --json
gantt spare list --project <id> [--q 电机] [--json]
```

- 草稿格式与 §5.1 的输出契约相同，AI 可以在里面带上 `fields`。
- `gantt spare import` 在应用开着时**不能写**（和 `gantt feishu write` 同一个判断）：插件是内存里的那份，CLI 写文件会被下一次插件的写回覆盖。所以 Agent 直调要求用户在应用里先关掉那个项目的备件视图，或者应用未运行。
- 撤销：`gantt spare revert <importId> --project <id>`，写一条反向调整。

### 5.3 图片

图片走应用的 `claude --tools`（读图能力在 Claude 侧，不在 CLI 里）：用户选图 → 宿主 `api.proc.spawn("claude", ["-p", …, "--allowedTools", "Read"])`，把路径交给它，按同一契约输出 JSON → 进预览 → 写入。`api.pickFiles`（宿主 1.7 新增）负责选图。

## 7. 飞书同步（P4）

### 7.1 两张表

**备件表**：序号、名称（主字段）、SKU、规格、分类（单选）、位置、库存、安全库存、单位、状态、`gantt_part_id`（隐藏）。

**日志表**：Entity、备件（**单向关联 → 备件表**）、类型（单选）、日期、数量、库存变化、领用人、操作人、备注、`gantt_log_id`（隐藏）。

关联单向：日志 → 备件，点开能穿透看备件；双向会在备件表生成一个随时间无限增长的反查列。

### 7.2 同步语义

- **手动**：只有一个「同步」按钮，无定时器。
- **备件表**：按 `sku`（缺 SKU 时按序号）匹配；两边都有的条**更新**本地最新库存；只在飞书有的行不删、不改，保留。
- **日志表**：只追加；已同步的记录 id 记在飞书插件的队列里（键 `log:<id>`），不重复创建。
- 推送失败留队列，下次「同步」重试；某一条失败不中断整批。

### 7.3 调用链

飞书插件新增命令，备件插件经 `api.commands.run` 调，和故障树调 `feishu-sync.push` 同一模式：

```
feishu-sync.parts.provision({ baseToken })               → { partsTableId, logsTableId }
feishu-sync.parts.sync({ projectId, target, seqs? })     → { created, updated, failed[] }
```

真正的建表 / 写记录仍由飞书插件的后台 Claude + `lark-cli` 完成，备件插件不碰 lark-cli。

## 8. 一致性与并发

- 写操作在插件层串行（一个 promise 队列），每次都基于「上一次写完的那份」计算，不读渲染时的旧值。
- 写回前校验不变量。
- 插件数据按账号分开（宿主 `plugins/<id>/data/accounts/<uuid>/`）；同一账号在两个窗口打开同一项目时，后写的覆盖先写的 —— 目前没有跨窗口合并，日志能看出发生了两次。
- 备件跟着项目，但**项目导出 / 云备份不带备件**（见 §12.1）。

## 10. 风险

1. **AI 直接写入、不确认**：错一条就进台账。补偿：日志不可删只可冲销、导入批次可整批撤销、日志带原文和置信度。建议后续在清单里给 `import` 条目加「待核对」标记。
2. **项目导出 / 云备份不带备件**：换电脑后备件丢失。需要宿主给插件开放「随项目导出」，或把备件并入 `.ganttproj` 的插件段（P5）。
3. **多人共享项目、备件不共享**：插件数据按账号存，另一个成员看不到。
4. **飞书表结构漂移**：用户改了列名或删了关联列，同步会失败；同步前读字段清单，缺列直接报「关联字段丢了，重新建表」。
