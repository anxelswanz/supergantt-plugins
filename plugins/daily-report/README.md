# 日报

把一段时间内在事项里记下的东西整理成一份 Markdown 日报：按类型分段（问题、风险、待办、你自己建的类型……），每段逐条编号，复制就能发。

## 用法

1. 启用后，工具条上多出「日报」视图
2. **选时间**：点「今天」「近 7 天」「近 30 天」，或者自己填开始日和结束日（含两端）。默认是今天
3. **选类型**：下面一排是 `In Progress` 加上这段时间里出现过的所有事项类型，带条数。默认全部勾上，全勾就是全展示；点掉哪个，日报里就不出那段
4. 想改随手改；点「预览」看 Markdown 渲染后的样子，点「编辑」回来
5. 点「复制」拿到 Markdown 原文，粘到飞书、GitHub、任何支持 Markdown 的地方

事项数据一变，日报会自动重新生成（手改的内容会被覆盖，改之前先复制）。

## 生成的样子

```markdown
# 日报 2026-11-02

> 共 5 条：问题 2 · 风险 1 · 待办 2；其中已关闭 1

## In Progress

1. COMBINED COMMISSIONING（进度 40%，负责人：张三，计划 11-20 完成）
   1. robot install（进度 10%，计划 11-08 完成）

## 问题

1. 供应商没回邮件（任务：电机安装，负责人：张三）
2. 夹具尺寸不对（10-30）
3. 图纸版本混乱 —— 已解决：统一用 V3

## 风险

1. 电机可能延期（高风险）

## 待办

1. 补一份验收清单
```

**In Progress** 列的是到结束日那天还在做的任务：没做完，而且已经有进度、有没关的阻碍、或者计划工期盖住了这一天（里程碑不算）。父任务和子任务都在做时，子任务缩进挂在父任务下面。

哪一类没有记录，那一整段就不输出（不会写「无」）。选了一段日期时，每条事项后面标记录日；单看一天时不标。未关闭的排在前面，同一类里急的在前；未分拣的事项单独一段，排最后。

## 设置

在 **设置 → 插件 → 日报** 里：

- **日报标题**：生成的第一行，后面自动接日期（一段日期时写成 `2026-10-01 ~ 2026-10-31`）
- **每条带上关联任务和负责人**
- **包含之前记的、还没关闭的**：开始日之前记下、到结束日仍未解决的事项也列进来，并标出原记录日

类型勾选直接记在插件设置里（`excludedKinds`），下次打开还是你上次的选择；新建的类型默认在日报里。

## 权限

不运行任何本机程序，只读事项数据。
