# 故障树分析

把一个问题或阻碍当成**顶事件**，用与门 / 或门一层层拆到基本原因；逐个标「已确认 / 已排除」，
自动推出哪条因果链成立、还剩哪些最小割集。

## 开始

- 在事项页对一条问题或阻碍点 ⋯ →「建故障树分析」，它就成为一棵树的顶事件
- 也可以在「故障树」视图里直接新建

## 画布

- 中间事件挂**或门**（任一输入发生即导致上层）或**与门**（全部同时发生才导致）
- 拆到底的是**基本事件** ○，暂时不拆的是**未展开事件** ◇
- 键盘：选中节点后 `Tab` 加子事件、`↵` 加同级、`空格` 改名、`⌫` 删除、`⌥←→` 调顺序、`⌘Z` 撤销

## 推导

- 基本事件标「已确认 / 已排除」后按门的逻辑往上推：成立的因果链染红，被排除的分支变淡
- 已确认、拆到底、又在成立链上的事件自动打「根因」角标
- 右栏列出**最小割集**（能单独导致顶事件的最小原因组合），悬停时在画布上高亮

## 根因与解决方案

- **根因**：角色是「原因」、验证为已确认、在成立的因果链上，并且下面没有更深的成立原因。
  不用另外写根因 —— 把排查到的那个事件标成「原因」+「已确认」，它就会打上「根因」角标
- **解决方案**：挂在根因下面的「对策」（标了「无效」的不算）

树上出现根因后，右栏「分析」里出现**解决方案卡**，根因节点的工具条上也有「确认解决方案…」。点开是一份**只读**的摘要，
不用再输入任何东西：

| | 内容 |
|---|---|
| 根因 | 确认的原因 |
| 因果链 | 顶事件 → … → 根因 |
| 解决方案 | 根因下的对策；一条都没有时写「未制定」 |
| 解决步骤 | 整棵树的事件按层级写成大纲（排查过程），每行带验证结果和日期，排除的也在 |

两个勾默认都开着：**关闭事项**（顶事件关联的那条标为已完成，结论里写上上面四块）、**同步到飞书**（装了飞书插件时出现；
加入同步队列并立即后台同步，由 Claude 对照多维表格的字段拆进哪几列）。确认时，根因下待做 / 进行中的对策标为已完成。`⌘↵` 确认。

- 确认后又改了树：卡片提示「确认后树又改过」，点「重新确认…」用最新的树更新事项
- **撤回**：对策状态改回确认前；事项恢复成确认前的样子（原来没关就重新打开，原来就关着就把结论改回原样；
  阻碍不会重新打开，只清掉结论）。飞书上的记录不动，队列里标为「有变更」
- `⌘Z` 只撤销树上的编辑，不碰事项；撤回方案用卡片上的「撤回」

## 标签与删除

- 标签上的 × 只是把这棵树收起来，树还在，「列表」里点一下就重新打开
- 删除在「列表」里，删之前会先确认

## 对策

节点可以是现象 / 原因 / 对策。对策用绿色虚线往下挂，记状态（待做 / 进行中 / 已完成 / 无效）
和截止日期，不参与推导。挂在顶事件下的是临时措施，挂在原因下的是根本对策。

## 其他

- 任何事件都能关联一条事项，事项页上会出现「故障树」标签
- 「复制大纲」把整棵树导出成缩进文本，贴进周报或邮件
- 树存在插件的 `data/trees.json`，按项目分开。卸载不删数据，重新安装后树都还在

## 权限

不运行任何本机程序。
