# gantt-spare-parts：发货单 → 备件台账

备件台账**跟着项目走**，一个项目一份，由 SuperGantt 的「备件」视图维护。
你（Agent）只负责**把单据变成结构化条目**，写入交给 `gantt spare`。

## 1. 先确定项目

```bash
gantt project list --json
gantt spare list --project <id 或 项目名> --json
```

- 只有用户明确说了项目名才直接指定；说不清就问，别猜。
- 先 `list` 看一眼：能认出已有条目（同一个 SKU 会入库而不是重复建）。

## 2. 从单据提取条目

对用户给的单据（图片用 Read 工具读，文字直接解析），按这个形状输出：

```jsonc
{
  "source": "DN-20261104（单号；没有就写供应商 + 日期）",
  "items": [
    {
      "name": "伺服电机",             // 必填
      "sku": "SM-400W",               // 单上明确印着才填，否则空串
      "spec": "400W / 3000rpm",
      "category": "电机",
      "location": "",                 // 单上通常没有，留空
      "unit": "台",                   // 单上写了就用，没写就空（默认个）
      "qty": 20,                      // 单上的数量，合并同货号
      "fields": [                     // 核心列装不下的信息放这里，标签用单上的原文
        { "key": "price", "label": "单价", "value": "1200" }
      ],
      "confidence": 0.9
    }
  ]
}
```

规则：

1. **一行单据一条**；同一货号出现多行时合并，数量相加。
2. **数量照单写，不要自己改**。单位按单上的（箱 / 台 / 个 / 米）。
3. **SKU 只在明确印着时填**。没有 SKU 的条目每次导入都会新建一条，所以导入前先在
   `gantt spare list` 里找有没有同名条目，有的话告诉用户「这条没型号，可能重复」。
4. 看不清的字段留空，**不要编造**；有猜测的 `confidence` ≤ 0.5。
5. 单价、金额、批次号、供应商料号这类都进 `fields`，标签用单上的原文列名。
6. 单上的合计行、抬头、运费、税，不进 `items`。

## 3. 写入

把上面那段 JSON 写进一个临时文件（例如 `draft-<单号>.json`），然后：

```bash
gantt spare push <文件> --project <id 或 项目名> --json
```

返回里：

- `created: [序号…]` —— 新建的条目
- `received: [[序号, 数量]…]` —— SKU 命中、入库的
- `skipped` —— 没名称等被跳过的，**要转告用户**
- `queued: true` —— 应用正开着，批次进了**收件箱**，插件几秒内自己入库。
  告诉用户「已放进收件箱，备件页现在开着的话几秒内会看到」

**不要**直接改台账 JSON 文件，也不要用 `--force` 绕过应用占用检测。
`--force` 只在用户明确知道应用没在用那个项目、并且坚持要求时才能用。

## 4. 核对

```bash
gantt spare list --project <id> --q <型号或名称> --json
```

- 数量对不上就**不要**自己「修正」库存：那属于「调整」，要写原因、由人在界面上做。
  告诉用户差多少，让用户在备件页点「编辑 / 入库」或整批撤销后重导。
- 导错了可以用 `gantt spare revert <importId> --project <id>` 整批回退（写反向调整，原记录保留），
  但**先问用户**再执行。

## 5. 汇总

一两句中文：新建几条、入库几条、跳过几条；有没有字段因为单据看不清而留空；有没有疑似重复。

## 边界

- **不做**「使用」「盘点」：这两步会直接改库存、要留操作人，必须在应用界面里由人确认。
- **不删**条目、不改别人做的条目。归档也要用户在界面上做。
- 台账里所有时间、序号都由程序生成，不要自己算。
